# Sprint 4.2 — Stream-Level Self-Diagnosis Engine

Implementation plan. **Local doc — do not push to `dev`.**
Built on branch `feat/4.1-unified-subscriber-memory` (per instruction).

## Objective

A daily cron `src/tasks/stream_self_diagnosis.py` that computes high-level
operational "stream" metrics per county, detects when a metric is below its
target for **3 consecutive days**, and writes a categorized diagnostic entry
(trend summary + concrete recommendations) into a dashboard warning-log table.
Observe-only — it never takes auto-actions (that's `cora_self_healing`'s job).

## Locked decisions (grill Q1–Q5 + defaulted Q6–Q8)

| # | Decision |
|---|----------|
| 1 | Output → **new `stream_diagnostics` table**, observe-only. Distinct from `cora_incident`/`cora_self_healing` (which auto-acts on monetization metrics). |
| 2 | Metrics → **config-driven `STREAM_METRICS` registry** in `config/stream_diagnostics.py`. Ship 4: `enrichment_rate`, `dialable_rate`, `sms_delivery`, `closer_conv`. |
| 3 | Daily history → **add 4 columns to `platform_daily_stats`**; the task **upserts** its metrics into the `(run_date, county_id)` row. 3-day streak = read last 3 rows. |
| 4 | Diagnosis → **hybrid**: deterministic rules produce structured `{category, magnitude, component, recommendations[]}`; LLM polishes prose `trend_summary`; **templated fallback** on LLM failure so the row always writes. |
| 5 | Lifecycle → **one open entry per breach episode**: open at day-3, update daily (`days_below`, summary, severity), set `resolved_on` on recovery. Mirrors `cora_incident` open/closed. |
| 6 | County scope → **per-county** (`hillsborough`, `pinellas`); `--county-id` arg. Forced by `platform_daily_stats` NOT-NULL composite key. |
| 7 | Severity → `yellow` at 3-day breach → escalate to `red` after **7** consecutive days **or** value < 50% of target. |
| 8 | Schedule → **08:30 UTC per county** (after CDS writes the daily row at 07:00). |

## Reuse (do not rebuild)

- **Cron pattern**: mirror `src/tasks/financing_intent_sweep.py` — `argparse` (`--county-id`, `--dry-run`), `get_db_context()`, `setup_logging()`, JSON result print, `__main__`.
- **Daily stats table**: `platform_daily_stats` (one row per `run_date, county_id`, upsert via `ON CONFLICT`). CDS writes it at 07:00; we update the same row.
- **Incident open/closed pattern**: copy the open/update/resolve SQL shape from `cora_self_healing.py` (`_find_open_incident` → most-recent unresolved row).
- **DB convention**: write migration files but apply DDL via a `scripts/apply_*.py` script (alembic CLI unusable — multi-head). Raw SQL via `sqlalchemy.text()` with named binds; never the ORM query API for data retrieval.
- **LLM**: reuse the platform's usage-logged Claude wrapper (confirm `src/services/claude_router.py` vs `compose_and_send.call_claude_with_usage`); wrap in try/except.

## Deliverables

### 1. Schema

**A. New table `stream_diagnostics`** — model in `src/core/models.py` + migration `fa101` + `scripts/apply_fa101_stream_diagnostics.py`.

```
stream_diagnostics
  id              BIGSERIAL PK
  county_id       VARCHAR(50)  NOT NULL
  stream          VARCHAR(50)  NOT NULL      -- logical stream group (e.g. 'lead_pipeline','outreach','closer')
  metric_name     VARCHAR(64)  NOT NULL      -- e.g. 'dialable_rate'
  severity        VARCHAR(16)  NOT NULL      -- 'yellow' | 'red'   (CHECK)
  observed_value  NUMERIC(10,4) NOT NULL
  target_value    NUMERIC(10,4) NOT NULL
  baseline_value  NUMERIC(10,4)              -- 7-day rolling mean, nullable
  days_below      INTEGER      NOT NULL
  category        VARCHAR(64)  NOT NULL      -- rule-classified breach category
  trend_summary   TEXT                       -- LLM-polished (or templated) prose
  recommendations JSONB        NOT NULL DEFAULT '[]'   -- structured recs (source of truth)
  detected_on     DATE         NOT NULL
  resolved_on     DATE                       -- NULL = open
  created_at      TIMESTAMPTZ  NOT NULL DEFAULT now()
  updated_at      TIMESTAMPTZ  NOT NULL DEFAULT now()
  UNIQUE (county_id, metric_name, detected_on)   -- one episode per metric/county/open-date
  INDEX (county_id, metric_name) WHERE resolved_on IS NULL   -- fast open-episode lookup
```

**B. 4 columns on `platform_daily_stats`** — migration `fa102` + apply script. All `NUMERIC(7,4) NULL` (matches existing kill-switch metric columns; NULL = "not computed this day"):
`enrichment_rate`, `dialable_rate`, `sms_delivery_rate`, `closer_conv_rate`.

### 3. Metric compute functions — `src/services/stream_metrics.py` (new)

One pure function per metric, `(db, county_id) -> float | None` (None when no denominator). Raw SQL, county-scoped. Definitions (confirmed against schema):

- **`compute_enrichment_rate`** — of properties scored in last 30d (`distress_scores` JOIN `properties` on county), fraction whose `owners` row has `(phone_1 OR email_1) IS NOT NULL AND contact_info_confidence IN ('high','medium')`.
- **`compute_dialable_rate`** — of `owners` (JOIN `properties` for county) with any phone, fraction where `phone_metadata` primary type ∈ (`mobile`,`landline`). *Open: confirm JSONB shape vs reuse `phone_deliverability_snapshots`.*
- **`compute_sms_delivery_rate`** — `message_outcomes` last 7d, `message_type='sms'`, `delivered_at IS NOT NULL` / total sms, scoped by `message_outcomes.county_id`.
- **`compute_closer_conv`** — `closer_calls` JOIN `subscribers` (county) last 30d, `call_outcome='committed'` / `call_outcome IS NOT NULL`.

Each returns a ratio in 0–1 (stored ×1 in the NUMERIC(7,4) column as a fraction, or ×100 — **pick one convention**; plan stores **fraction 0–1** to match targets).

### 4. Diagnosis engine — `src/services/stream_diagnosis.py` (new)

- `classify_breach(metric_name, history: list[float], target) -> dict` — pure rules → `{category, magnitude_pct, component, severity, recommendations}`. Deterministic, fully unit-tested. Severity per Q7.
- `polish_summary(structured: dict) -> str` — try LLM wrapper; on any exception return `_template_summary(structured)`. Try/except per CLAUDE.md.
- `_template_summary(structured) -> str` — deterministic prose fallback.

### 5. The task — `src/tasks/stream_self_diagnosis.py` (new)

Per `--county-id` (default: run both configured counties), per metric in `STREAM_METRICS`:
1. `value = compute(db, county_id)`; **upsert** into today's `platform_daily_stats` row (`ON CONFLICT (run_date, county_id) DO UPDATE SET <column>=...`). Create row if CDS hasn't yet.
2. Read last 3 rows (incl. today) for that column → `streak_below = all 3 < target` (direction-aware).
3. **Find open `stream_diagnostics`** episode for `(county, metric)`:
   - streak_below & no open → INSERT (severity, category, recs, summary, `days_below=3`, `detected_on=today`).
   - streak_below & open → UPDATE `days_below`, severity (maybe →red), summary, `updated_at`.
   - not below & open → UPDATE `resolved_on=today` (close).
4. `--dry-run` computes + classifies but writes nothing; prints JSON.

### 6. Cron — `scripts/cron/crontab.txt`

## Tests — `tests/test_stream_self_diagnosis.py` (real Postgres, rolled back)

1. Each compute fn returns correct ratio on seeded data; `None` on empty denominator.
2. `classify_breach`: severity yellow at 3d; red after 7d; red when value < 50% of target; category + recs present.
3. `polish_summary` falls back to template when LLM unavailable (patch wrapper to raise) — never raises.
4. Streak detection: 2-day dip → no diagnostic; 3-day → opens one; day-4 → updates same row (no dup); recovery → sets `resolved_on`.
5. Upsert into `platform_daily_stats` works whether or not CDS created the row.
6. `--dry-run` writes nothing.
7. Idempotency: running twice same day → still one open episode, no duplicate row.
